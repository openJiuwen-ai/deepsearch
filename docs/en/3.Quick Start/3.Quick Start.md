DeepSearch is a knowledge-augmented, high-performance deep retrieval and research engine. It uses structured knowledge and LLMs with tools to deliver enterprise Agentic AI search and research. This document walks through using the DeepResearch agent for report-oriented research and the DeepSearch agent for complex question answering.

## 1. Preparation

> **Note**: The product has separate front-end and back-end projects. Before you start, ensure both are deployed and running. If not, follow the [DeepSearch Full Edition installation guide](../2.Installation%20Guide/DeepSearch%20Full%20Edition/README.md).

### 1. Get an LLM API key

DeepSearch needs an LLM. Purchase or host a model from a provider. The steps below use Huawei Cloud as an example.

* Open the [ModelArts deployment console](https://console.huaweicloud.com/modelarts/?locale=zh-cn&region=cn-southwest-2#/model-studio/deployment) (online inference).

* Pick a model and click **Enable service**.

  ![images](../images/quick-start/华为云-模型广场.png)

* After enabling, open **Invocation guide** for model details.

  ![images](../images/quick-start/华为云-模型配置.png)

* Open **OpenAI-compatible API** and note the *API endpoint* and *model* parameter.

* Under **API key management**, create a key per the console.

> Details: [Huawei Cloud ModelArts MaaS user guide](https://support.huaweicloud.com/usermanual-maas-modelarts/maas-modelarts-0195.html)

DeepResearch uses a web augmentation service (e.g. [Tavily](https://www.tavily.com/)) to fetch online information.

![images](../images/quick-start/Tavily-api-key.png)

> Tavily: [official documentation](https://docs.tavily.com/documentation/about)

### 3. Model configuration

In **Model management**, three model types are supported:
1. **LLM**: Large language model — text in, text out.
2. **Embedding**: Text-to-vector embedding model.
3. **VLM**: Vision-language model — image in, image out.

Select a model type, then click **Add model**. Fill in **Model name**, **Model ID**, **API key**, **Base URL**, and **Description**.

* **Model name**: Display name; you choose.
* **Model ID**: Provider's model id (matches Huawei *model* parameter).
* **API key**: From the provider (Huawei *API Key*).
* **Base URL**: Provider API base URL (Huawei *API address*).
* **Description**: Optional notes.

  ![images](../images/quick-start/快速上手-模型配置.png)

Test the model:

* In model management, click **Test** on a model.
* Pick a sample prompt.
* Click start; **Test succeeded** means configuration is OK.

  ![images](../images/quick-start/快速上手-模型测试.png)

> If testing fails, double-check endpoint, model id, and key.

#### Agent configuration

Click **Configure** next to the DeepResearch agent.

![Agent config entry](../images/quick-start/智能体配置入口.png)

Three tabs group the settings.

> Click **Save configuration** when done.

#### General

General settings cover interaction and planning options.

* **Enable Q&A interaction**: When on, the agent asks clarifying questions before planning the task.
* **Enable outline interaction**: When on, users can review and revise the report outline over multiple rounds before research begins.
* **Enable dependency model**: When off, sections are generated in parallel. When on, sections are serialized with dependencies. Dependency mode improves report consistency but increases generation time — enable as needed.
* **Enable provenance**: When on, results show information sources.
* **Enable user feedback optimization**: When on, after a report is generated you can select text passages and apply AI rewriting (expand, polish, condense, or supplemental search).
* **Enable VLM chart generation**: When on, the vision model iteratively refines generated charts. This increases report generation time — enable as needed.
  * **VLM model**: A VLM model must first be configured in **Model management**, otherwise this option cannot be enabled.
  * **Max iterations**: Controls how many times the VLM refines each chart (1–3). Higher values produce more detailed charts but take longer.
* **Number of sections**: Max report sections (1–15); higher values mean more detailed planning.

#### Search

![搜索配置](../images/quick-start/智能体搜索配置.png)

Search settings cover search mode, search sources, and request rate control.

**Search mode**: Choose how to search.
- **Local search**: Knowledge base only.
- **Web augmentation**: Use a web augmentation engine.
- **Hybrid search**: Combine local and web search.

> The selected search mode determines which search sources are configurable below.

**Search sources**: Configure sources based on the selected mode.

![Search config](../images/quick-start/智能体联网增强引擎配置.png)

- **Web augmentation engine**: Click **Configure** to add engines. Supports iFlytek Search, Petal AI Q&A, Tavily (supports targeted source retrieval), Google, Jina, Bocha, Perplexity, Serper, and custom engines (as shown above).
- **Local knowledge base**: Click **Configure** to select one or more knowledge bases.

  Knowledge base status:
  - **Available (green)**: Ready to use.
  - **Processing (gray)**: Still being indexed; not yet available.
  - **Failed (red)**: Processing failed; cannot be used.

  > Only knowledge bases in **Available** status are queried during research. Create and sync knowledge bases in the Knowledge Base management page before use.

**Request rate control**: Limit how fast requests are sent to the web augmentation engine.
- QPS: requests per second; default 0 means unlimited.
- Decimal values are supported — e.g. 0.5 means 1 request every 2 seconds.

  > Setting a reasonable QPS prevents hitting engine rate limits and controls resource usage.

#### Templates (optional)

To control report structure, use templates.

* **Available templates**: Pick from the list; the agent formats the report accordingly.
* **Import template**: **Upload new template** from a sample.
  * **Extract**: Auto-extract structure from Markdown, HTML, Word, or PDF.
    </br>![Template extract](../images/quick-start/模板提取生成.png)
  * **Use as template**: Use a Markdown file directly as the template.
    </br>![Pick template](../images/quick-start/选择模板.png)

> Templates are optional.
> Uploaded templates or sample reports must be no larger than `50 MB` per file. Very large or structurally complex documents may fail to parse, so splitting the file and retrying is recommended.

#### Model assignment

Assign models per research stage for quality vs cost.

![Model config](../images/quick-start/模型配置.png)

**Basic**

- **General model** (required): Default for all stages when advanced slots are empty. Prefer a strong general model.

**Advanced** (optional)

Per-stage overrides; unset stages use the general model.

- **Outline generation**: Prefer a strong reasoning model to accurately understand intent and reduce hallucinations.
- **Information gathering**: Lightweight model is often enough for quick summarization.
- **Report writing**: Prefer models strong at code/math for accuracy and professionalism.

> Advanced is optional. All configured models must support **function calling** so the agent can invoke tools correctly.

#### Choose the chat model

Use the model picker in the top-right of the chat.

![Pick model](../images/quick-start/选择模型.png)

> You must select a model. Context under 128K may limit long research reports.

### 2. Conversation flow

#### 2.1 Ask a question

![images](../images/quick-start/对话框-输入框.png)

> **Notes**  
> - Type in area **1**, send with **2**.  
> - Two modes: HITL (human-in-the-loop) and non-HITL.

##### 2.1.1 HITL mode

In HITL mode, if the relevant interaction options are enabled, multiple rounds of interaction occur:

**User intent interaction** (enable Q&A interaction in General settings):

1. You ask; DeepSearch/DeepResearch may ask follow-ups.
   - Yellow indicator (**1**) = waiting for your reply.
   - Type feedback in **2** and send.  
   </br>![images](../images/quick-start/对话框-HITL模式系统回复1.png)
2. After your reply, report outline generation continues.
   - Green (**3**) = feedback received.
   - **4** shows your message; **5** shows outline generation starting.  
   </br>![images](../images/quick-start/对话框-HITL模式系统回复2.png)

**Outline interaction** (enable outline interaction in General settings):

1. **Outline review**: After the outline is generated, execution pauses and waits for your confirmation or edits.
   </br>![images](../images/quick-start/大纲HITL.png)
2. **Outline editing**: Click **Start research** to accept the outline, or refine it first. Two editing methods are available:
   - **Refine via feedback**: Submit revision comments in the chat; the system regenerates the outline based on your input.
     </br>![images](../images/quick-start/大纲HITL通过反馈修改.png)
   - **Edit manually**: Click the edit button next to the outline title to directly modify titles, summaries, etc.
     </br>![images](../images/quick-start/大纲HITL编辑.png)
3. **Generate report**: You can revise the outline as many times as needed. Once satisfied, click **Start research** and DeepSearch begins writing the full report.

#### 3.2 Edit view

When **Enable user feedback optimization** is on, click the edit button to enter edit mode.

![images](../images/quick-start/报告-编辑按钮.png)

In edit mode, the following editing methods are available:
1. **Manual report editing**: Edit the report text directly. Changes can be synced manually or will auto-save within a few seconds. **Note**: After manual editing, always sync the report before using AI rewrite.
2. **AI rewrite**: The report is rendered as text blocks. Hover over a block to reveal the star sidebar button (AI rewrite) on the left. Hovering over the sidebar highlights the entire block.

##### 3.2.1 Manual report editing
![images](../images/quick-start/报告编辑-直接编辑报告.png)
![images](../images/quick-start/报告编辑-直接编辑报告_同步完成.png)
You can edit report text directly in the edit interface. While editing, a **Pending sync** indicator appears in the top-left of the report. After finishing, click **Sync** in the top-right to save, or wait 3 seconds for auto-save. On success, the indicator changes to **Synced**.

![images](../images/quick-start/报告-AI改写侧边栏.png)

##### 3.2.2 AI rewrite
Click the AI rewrite button to open the rewrite input panel. Choose **Polish / Expand / Condense**, etc., enter your intent in the input box, then click send to trigger the model rewrite.

> Note: Selecting text or manually editing the report does not trigger AI rewriting. After manually editing the report, sync first, then use the sidebar for AI rewriting.

![images](../images/quick-start/报告编辑-AI改写输入框.png)

After rewriting, the action appears in the chat and a new report card is generated. The rewritten section is also updated in the report view. Supported rewrite operations:
* **Polish**: Improve readability and flow.
* **Expand**: Add more detail to the selected text.
* **Condense**: Make the selected text more concise.
* **Supplemental search**: Search for additional related information and incorporate it into the text. Two sub-modes:
  * **Selection only**: Rewrite only the selected text in-place without affecting other content.
  * **Smart linked rewrite**: Rewrite the entire minimum enclosing section, maintaining coherence.
* **Add Task**: Run an additional research task focused on the section containing the selected text and rewrite that section.

![images](../images/quick-start/报告编辑-改写部分高亮提示.png)
After a successful rewrite, the modified text is highlighted in light green so you can quickly locate the changes.

![images](../images/quick-start/报告编辑-AI改写结果.png)

AI rewriting has a round limit. Plan your revisions accordingly — once the limit is reached, AI rewriting is no longer available for that report.

![images](../images/quick-start/报告编辑-AI改写轮次上限.png)

##### 3.2.3 Truth Verification
After a report is generated, you can select specific conclusions, data, or factual statements and request a fact-check to confirm whether the selected content is adequately supported by source material.

![images](../images/quick-start/报告编辑-真实性核验.png)

Select a paragraph in the generated report and trigger fact-checking. Once complete, a verification result badge appears to the right of the paragraph. Click the badge to view the result.

![images](../images/quick-start/报告编辑-真实性核验展示.png)

## 3. Using the DeepSearch Agent

Deep Search mode is optimized for complex search tasks. To use the Deep Search mode in openJiuwen, follow these steps:

### 1. Select Deep Search mode

In **Task space**, select **Deep Search** mode.

![Deep Search mode in task space](../images/quick-start/deep-search/1_taskspace.jpeg)

### Deep Search Configuration (steps 2 to 4)

#### 2. General settings

In **General** tab, configure search process settings such as question routing, actions explored limit and time limit.

**Question routing** saves LLM tokens by routing simple questions to a lightweight ReAct agent, and triggering Deep Search only for complex questions. 

**Actions explored limit** controls the maximum number of actions the agent can explore per question during the search process. It takes values between 1 and 200.

**Time limit** sets the maximum duration for the search process. It takes values between 1 and 3600 seconds.

![Deep Search general settings](../images/quick-start/deep-search/2_general.jpeg)

#### 3. Search settings

In the **Search** tab, select the source used by the search process. Deep Search supports two modes:

- **Online Enhancement**: use a configurable web search engine and a web fetch provider.
- **Local Search**: use a configured local knowledge bases.

![Deep Search search mode selection](../images/quick-start/deep-search/3_search.jpeg)

For **Online Enhancement**, click **Configure** under **Web Search Engine** to choose a provider. Multiple provider types are supported, including Xunfei Search, Petal AI Q&A, Tavily, Google, Jina, Serper, Bocha, Perplexity, and custom engines. Enter the provider API key, optional search URL, and any provider-specific extension parameters as JSON. This configuration is independent of web fetching, so the search provider can be changed without changing the fetch provider.

![Deep Search web search engine configuration](../images/quick-start/deep-search/3_search_online_search.jpeg)

Click **Configure** under **Web Fetch Provider** to configure page retrieval separately. The current fetch-provider implementation supports **Jina**. Enter the Jina API key, optionally provide a base URL, and add provider-specific extension parameters as JSON.

![Deep Search web fetch provider configuration](../images/quick-start/deep-search/3_search_online_fetch.jpeg)

For **Local Search**, select **Local Search** and configure the local knowledge base to use.

![Deep Search local search configuration](../images/quick-start/deep-search/3_search_local.jpeg)

#### 4. Model settings

In **Model** tab, configure planning and search models. The **planning model** is used once at the beginning for question parsing, so a strong general-purpose model is recommended.

![Deep Search model settings](../images/quick-start/deep-search/4_model.jpeg)

### 5. Enter a Deep Search question

Enter your Deep Search question in Task space and send it.

![Deep Search question input](../images/quick-start/deep-search/5_question.jpeg)

### 6. Search process starts

Deep Search begins the retrieval process and shows question-parsing outputs, including unknown entities to search and related statistics.

You can click **DeepSearch Explorer** for a more detailed view of the full Deep Search process.

![Deep Search running state](../images/quick-start/deep-search/6_searching.jpeg)

### 7. Get the answer

After the search process completes, the system displays the final answer.

![Deep Search final answer](../images/quick-start/deep-search/7_answer.jpeg)
