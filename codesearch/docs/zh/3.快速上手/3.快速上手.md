# 快速开始

> **说明**
>
> - 当前索引仅处理 Python（`.py`）文件。非 Python 仓库会得到 0 个文件。
> - `--repo` / `repo_path` 必须是**本地目录**；远程仓库请先 `git clone`。
> - `--collection` 是你起的 Milvus 集合名；检索阶段只传集合名，不再传路径。

## 命令行

### 1. 索引仓库

先准备本地代码目录（若仓库在网上，先 clone）：

```sh
git clone <git-url> /path/to/your/repo
```

```sh
codesearch index --repo /path/to/your/repo --collection my_repo
```

输出示例：

```
Indexed 132 files (132 new, 0 reused), 890 chunks inserted.
```

重复索引未变更的仓库时会显示 `(0 new, 132 reused)`，表示增量去重生效。

常用参数：

| 参数 | 说明 |
|---|---|
| `--collection` | 集合名称（实际集合名会加产品前缀与模式版本） |
| `--revision` | 版本标签，任意字符串；同一集合可容纳多个版本 |
| `--max-files N` | 仅索引前 N 个文件，适合先做小规模试点 |
| `--no-trigram` | 跳过三元组字段，显著降低存储占用，代价是失去精确子串检索 |
| `--reset` | 重建集合（清空已有数据） |
| `--milvus-host` / `--milvus-port` | 指定非默认的 Milvus 实例 |

### 2. 检索

检索会调用两个 LLM：

| 角色 | 职责 | 默认 `model_name` | 环境变量 |
|---|---|---|---|
| **main** | 多轮决策：搜什么、何时提交 | `openai/gpt-5` | `CODESEARCH_LLM_MODEL` |
| **filter** | 对命中 chunk 做逐行相关区间提取 | `openai/gpt-5-mini` | `CODESEARCH_FILTER_LLM_MODEL` |

只配密钥与端点即可使用默认模型；换 Ollama / 自建网关时请同时改模型名。
推荐写 `.env`（覆盖同名 export）；无 `.env` 时再用 `export`：

```sh
cp .env.example .env   # 填写 CODESEARCH_LLM_API_KEY / CODESEARCH_LLM_BASE_URL 等
# 或：
# export CODESEARCH_LLM_API_KEY="your-key"
# export CODESEARCH_LLM_BASE_URL="https://api.openai.com/v1"
# export CODESEARCH_LLM_MODEL="openai/gpt-5"            # 可选
# export CODESEARCH_FILTER_LLM_MODEL="openai/gpt-5-mini"
```

```sh
codesearch search --collection my_repo --query "TypeError when calling foo() with empty list" --top-k 10
```

问题描述较长时可用文件传入：

```sh
codesearch search --collection my_repo --query-file issue.txt --top-k 20
```

输出示例：

```
Termination: submitted | turns=6 | tokens=48213in/1876out
 1. src/utils/foo.py (L42-L57)
 2. src/core/handler.py (L103-L120)
```

各终止方式的含义见 [FAQ](../5.FAQ/README.md)。

## Python API

```python
import asyncio
from openjiuwen_codesearch import CodeSearchConfig, CodeSearchRetriever

async def main():
    config = CodeSearchConfig.from_env()
    async with CodeSearchRetriever(config, collection_name="my_repo") as retriever:
        report = await retriever.index_repository("/path/to/repo", revision="v1")
        print(report)  # 文件总数 / 新增 / 复用 / 插入片段数

        result = await retriever.search("问题描述...", revision="v1", top_k=20)
        print(result.termination, result.total_input_tokens, result.total_output_tokens)
        for hit in result.hits:
            print(f"{hit.file_path} L{hit.start_line}-L{hit.end_line}")

asyncio.run(main())
```

### 自定义模型

不设 `CODESEARCH_LLM_MODEL` / `CODESEARCH_FILTER_LLM_MODEL` 时，分别默认
`openai/gpt-5` 与 `openai/gpt-5-mini`。也可在代码里为 main / filter 指定任意
OpenAI 兼容端点与模型名：

```python
from openjiuwen_codesearch.config.llm import LLMConfig, LLMSuite

config = CodeSearchConfig(
    llm=LLMSuite(
        main=LLMConfig(
            model_name="qwen3:32b",
            api_key="your-key",
            base_url="http://localhost:11434/v1",
        ),
        filter=LLMConfig(
            model_name="qwen3:8b",
            api_key="your-key",
            base_url="http://localhost:11434/v1",
            max_tokens=2048,
        ),
    )
)
```

### 调整检索行为

```python
config.agent.max_turns = 30            # 允许更深入的检索
config.agent.stagnation_rounds = 5     # 更晚触发提前终止
config.agent.retrieve_topk = 10        # 返回更少但更精准的结果
```

## 评测

在 ContextBench 数据集上评估检索质量。

`python -m benchmarks.contextbench.runner` 会先检索写出预测，再**自动**调用
`contextbench.evaluate` 打分（见 `benchmarks/contextbench/exporter.py` 的
`run_eval`）。依赖请装产品 **`[bench]`**（pandas/pyarrow 读数据集 +
tree-sitter* 评分）；不要用上游 `requirements.txt` 代替——它缺 pandas，且
在 Python ≥3.12 上 `tree-sitter-languages` 常无 wheel。

```sh
# 在 monorepo 根执行（见仓库根 `.gitmodules`）
git submodule update --init --recursive
```

将数据集文件放入 `codesearch/third_party/contextbench/data/` 后，在
`codesearch/` 目录运行：

```sh
pip install -e '.[bench,milvus,llm]'   # 评测 I/O+评分；检索另需 milvus/llm
# 配置 CODESEARCH_LLM_* 与可用的 Milvus
python -m benchmarks.contextbench.runner --num-instances 32
# 默认引擎为 graph；可用 --engine react 或 --engine retropus 覆盖
```

输出（默认 `./results/`）：

- 预测：`[N]<时间戳>__agent_topk=....jsonl`
- 单实例指标：同名文件加后缀 `_metrics.jsonl`（runner 正常结束时自动生成）
- 汇总：同名文件加后缀 `_summary.json`

若评分报 `Tree-sitter not available`，在当前环境重新执行
`pip install -e '.[bench]'` 即可（旧环境可能从未装上 tree-sitter*）。
