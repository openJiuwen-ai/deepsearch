# 产品简介

**openJiuwen-CodeSearch** 是一款面向代码仓库的智能体检索引擎。输入一段问题
描述（如 GitHub Issue、缺陷报告、功能诉求），输出"要解决它应当查看哪些文件的
哪些行"。本系统以 openJiuwen agent-core 能力为基础，由检索智能体自主完成
查看仓库结构、多策略搜索、扩展上下文、筛选与提交等步骤。

## 应用场景

- **缺陷定位**：给定 Issue 或缺陷报告，定位到需要修改的函数与代码行，作为
  自动修复（issue-to-patch）流水线的第一环。
- **代码问答上下文供给**：为"这个功能在哪实现""这个报错从哪来"等问题提供
  精确到行的代码依据。
- **大型仓库导航**：在陌生的大规模仓库中，以自然语言描述换取相关代码切片。

## 核心特性

### 智能体式多轮检索

检索智能体拥有五类工具：查看仓库文件结构、多策略搜索代码、按行号扩展上下文、
删除误检片段、提交最终结论。它在多轮循环中自主决策，逐步积累与问题相关的
代码片段，直到有把握提交。

采用双模型协同：高能力模型负责搜索决策，轻量模型负责在检索结果中逐行提取
真正相关的代码行。这一设计使高能力模型只处理精炼后的内容，在保证质量的同时
显著降低成本。

### 面向代码的混合索引

- **语法感知切块**：按函数与类边界切分代码，每个片段都是完整的语义单元，
  避免固定行数切分导致的语义割裂。
  **当前仅支持 Python（`.py`）**；其它语言需扩展 `Chunker`。
- **双路稀疏检索**：标准词元检索处理语义关键词；字符三元组检索处理
  `data.sum()`、堆栈跟踪等包含符号的精确子串。二者互补覆盖不同的查询形态。
- **增量索引**：按文件内容哈希去重，同一仓库的多个版本共享未变更文件的索引，
  重复索引的成本接近于零。
- **可选稠密检索**：支持接入 embedding 服务，与稀疏检索加权融合。

### 双引擎等价实现

检索循环有两种执行形态：openJiuwen 工作流图引擎（默认，具备节点级可观测性）
与纯代码循环引擎（无框架依赖的兜底形态）。两者共享同一份阶段逻辑，测试锁定
其输出逐字节一致。

### 面向服务的工程能力

- 多形态交付：源码、Docker 镜像、正式 whl（含 `openjiuwen-search-base`）；
- 运行隔离：每次请求持有独立上下文，同进程并发互不串扰；
- 多产品共存：集合以产品前缀与模式版本命名，可与其他检索产品共用同一
  Milvus 实例；
- 完整的超时控制、有界并发、连接生命周期管理与 token 用量统计。
- HTTP 服务不含鉴权，索引范围由 `CODESEARCH_INDEX_ROOTS` 白名单约束
  （未配置则拒绝索引）。

## 系统架构

```
┌──────────────── 索引（离线） ────────────────┐
│  代码仓库 → 语法感知切块 → Milvus 双路稀疏索引  │
│  增量：文件哈希去重，多版本共享未变更文件        │
└────────────────────────────────────────────┘
┌──────────────── 检索（在线） ────────────────┐
│  问题描述 → 检索智能体（决策模型 · 筛选模型 ·   │
│            片段记忆 · 五类工具）→ 文件+行区间   │
└────────────────────────────────────────────┘
```

系统按单向依赖分层：`domain ← config ← algorithm ← framework ← api`。
search 场景的公共能力（LLM 适配、embedding 客户端、向量库基建、工作流节点
模板等）沉淀在独立的 `openjiuwen-search-base` 包中，供 openJiuwen 系列检索
产品复用。

详细的架构说明与扩展方式见[开发指南](../4.开发指南/README.md)。
