# 产品简介

**openJiuwen-CodeSearch** 是基于 **openJiuwen agent-core** 构建的 Agentic 代码检索引擎：
输入一段 GitHub issue / 问题描述，输出"解决它应查看的代码文件与行号区间"。
面向缺陷定位（code localization）、代码问答的上下文供给、以及自动修复流水线的第一环。

## 核心能力

- **多轮自主检索智能体**：主模型负责搜索决策（查看仓库地图、双模式搜索、按行展开上下文、
  维护片段记忆、提交结论），轻量过滤模型逐行提取相关代码，双模型架构控制成本；
- **双 BM25 索引**：标准词元检索 + 字符三元组检索（可精确匹配 `data.sum()`、
  堆栈跟踪等含符号子串），可选稠密向量混合检索；
- **语法感知切块**：按函数/类边界切分代码，保留完整语法单元与调用关系；
- **增量索引**：按文件内容哈希去重，同一仓库多个版本共享未变更文件的索引；
- **双引擎等价实现**：openJiuwen workflow 图形态（默认，Studio/Ops 可观测）与
  纯代码循环形态共享同一份阶段逻辑，输出逐字节一致；
- **运行隔离**：per-run context，同进程多请求并发互不串扰。

## 系统架构

```
┌────────── 索引（离线，无需 LLM key） ──────────┐
│ 本地仓库 → AST 切块 → Milvus（双 BM25 索引）    │
└────────────────────────────────────────────┘
┌────────── 检索（在线） ─────────────────────────┐
│ issue → 检索智能体（决策模型 + 过滤模型 + 片段记忆）│
│       → [文件 + 行号区间] 列表                   │
└────────────────────────────────────────────┘
```

分层设计（依赖方向单向）：`domain ← config ← algorithm ← framework/openjiuwen ← api`，
详见 [开发指南](../4.开发指南/README.md)。

## 与 openJiuwen 生态的关系

CodeSearch 与 [openJiuwen-DeepSearch](../../../../deepsearch) 为同仓并列的两个独立产品，
共享 agent-core 框架与相同的架构范式（算法/框架分层、BaseNode 节点模板、
workflow 图编排、运行隔离），互不依赖。
