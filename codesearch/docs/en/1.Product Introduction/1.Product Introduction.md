# Product Introduction

**openJiuwen-CodeSearch** is an agentic code retrieval engine built on
**openJiuwen agent-core**: given a GitHub issue or problem description, it returns
the code files and line ranges most relevant to solving it. It targets fault
localization, context supply for code Q&A, and the first stage of automated
repair pipelines.

## Core capabilities

- **Multi-turn autonomous retrieval agent**: a decision model drives the search
  (repo map, dual-mode search, line-range expansion, snippet-memory curation,
  final submission) while a lightweight filter model extracts relevant lines —
  a two-model architecture that keeps cost under control;
- **Dual BM25 indexing**: token-level BM25 plus character-trigram BM25 for exact
  substring matches (`data.sum()`, stack traces), with optional dense hybrid retrieval;
- **Syntax-aware chunking**: functions/classes as complete syntactic units, with
  call-graph metadata;
- **Incremental indexing**: content-hash dedup; multiple revisions of a repo share
  the index of unchanged files;
- **Two equivalent engines**: the openJiuwen workflow graph form (default,
  observable in Studio/Ops) and a plain-loop fallback share the same stage logic,
  with byte-identical outputs locked by tests;
- **Run isolation**: per-run context; concurrent requests in one process never
  interfere.
