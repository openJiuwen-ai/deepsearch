# Quick Start

> **Note**
>
> - Indexing currently covers Python (`.py`) files only.
> - `--repo` / `repo_path` must be a **local directory**; clone remotes first.
> - `--collection` is a Milvus name you choose; search uses that name only.

## Command line

### 1. Index a repository

Prepare a local checkout if the code lives online:

```sh
git clone <git-url> /path/to/your/repo
```

```sh
codesearch index --repo /path/to/your/repo --collection my_repo
```

```
Indexed 132 files (132 new, 0 reused), 890 chunks inserted.
```

Re-indexing an unchanged repository shows `(0 new, 132 reused)` — incremental
deduplication at work.

| Option | Description |
|---|---|
| `--collection` | Collection name (a product prefix and schema version are added automatically) |
| `--revision` | Version label, any string; one collection can hold many revisions |
| `--max-files N` | Index only the first N files — useful for a small pilot run |
| `--no-trigram` | Skip the trigram field to cut storage significantly, at the cost of exact-substring search |
| `--reset` | Rebuild the collection (drops existing data) |
| `--milvus-host` / `--milvus-port` | Target a non-default Milvus instance |

### 2. Search

Search calls two LLMs:

| Role | Job | Default `model_name` | Env |
|---|---|---|---|
| **main** | Multi-turn decisions: what to search, when to submit | `openai/gpt-5` | `CODESEARCH_LLM_MODEL` |
| **filter** | Per-chunk line-range extraction | `openai/gpt-5-mini` | `CODESEARCH_FILTER_LLM_MODEL` |

Key + base URL alone use the defaults; change model names when using Ollama or another gateway.
Prefer `.env` (overrides same-named exports); use `export` when no `.env` applies:

```sh
cp .env.example .env   # fill CODESEARCH_LLM_API_KEY / CODESEARCH_LLM_BASE_URL, etc.
# or:
# export CODESEARCH_LLM_API_KEY="your-key"
# export CODESEARCH_LLM_BASE_URL="https://api.openai.com/v1"
# export CODESEARCH_LLM_MODEL="openai/gpt-5"            # optional
# export CODESEARCH_FILTER_LLM_MODEL="openai/gpt-5-mini"
codesearch search --collection my_repo --query "TypeError when calling foo() with empty list" --top-k 10
```

For long problem statements, pass a file:

```sh
codesearch search --collection my_repo --query-file issue.txt --top-k 20
```

```
Termination: submitted | turns=6 | tokens=48213in/1876out
 1. src/utils/foo.py (L42-L57)
 2. src/core/handler.py (L103-L120)
```

Termination values are explained in the [FAQ](../5.FAQ/README.md).

## Python API

```python
import asyncio
from openjiuwen_codesearch import CodeSearchConfig, CodeSearchRetriever

async def main():
    config = CodeSearchConfig.from_env()
    async with CodeSearchRetriever(config, collection_name="my_repo") as retriever:
        report = await retriever.index_repository("/path/to/repo", revision="v1")
        print(report)

        result = await retriever.search("problem statement...", revision="v1", top_k=20)
        print(result.termination, result.total_input_tokens, result.total_output_tokens)
        for hit in result.hits:
            print(f"{hit.file_path} L{hit.start_line}-L{hit.end_line}")

asyncio.run(main())
```

### Custom models

Without `CODESEARCH_LLM_MODEL` / `CODESEARCH_FILTER_LLM_MODEL`, defaults are
`openai/gpt-5` and `openai/gpt-5-mini`. You can also set main / filter explicitly
in code for any OpenAI-compatible endpoint:

```python
from openjiuwen_codesearch.config.llm import LLMConfig, LLMSuite

config = CodeSearchConfig(
    llm=LLMSuite(
        main=LLMConfig(
            model_name="qwen3:32b",
            api_key="your-key",
            base_url="http://localhost:11434/v1",
        ),
        filter=LLMConfig(
            model_name="qwen3:8b",
            api_key="your-key",
            base_url="http://localhost:11434/v1",
            max_tokens=2048,
        ),
    )
)
```

### Tuning retrieval

```python
config.agent.max_turns = 30            # deeper search
config.agent.stagnation_rounds = 5     # stop later when no new findings
config.agent.retrieve_topk = 10        # fewer but more precise results
```

## Benchmarking

Measure retrieval quality on ContextBench.

`python -m benchmarks.contextbench.runner` writes predictions, then **automatically**
runs `contextbench.evaluate` (`run_eval` in `benchmarks/contextbench/exporter.py`).
Install the product **`[bench]`** extra (pandas/pyarrow for dataset I/O +
tree-sitter* for scoring). Do **not** treat upstream
`third_party/contextbench/requirements.txt` as equivalent — it omits pandas and
often lacks wheels for `tree-sitter-languages` on Python ≥3.12.

```sh
# from codesearch/; ContextBench is optional and is not fetched by clone/CI
bash scripts/fetch_contextbench.sh
# mirror: CONTEXTBENCH_URL=<mirror> bash scripts/fetch_contextbench.sh
# existing checkout: export CONTEXTBENCH_DIR=/path/to/ContextBench
```

Put dataset files under `codesearch/third_party/contextbench/data/` (or set
`CONTEXTBENCH_PARQUET`), then from `codesearch/`:

```sh
pip install -e '.[bench,milvus,llm]'   # bench I/O+scoring; milvus/llm for retrieval
# set CODESEARCH_LLM_* and a reachable Milvus
python -m benchmarks.contextbench.runner --num-instances 32
# default engine is graph; pass --engine react or --engine retropus to override
```

Outputs under `./results/` by default:

- predictions: `[N]<timestamp>__agent_topk=....jsonl`
- per-instance metrics: same path with `_metrics.jsonl` (written when the runner finishes)
- aggregate summary: same path with `_summary.json`

If scoring fails with `Tree-sitter not available`, re-run
`pip install -e '.[bench]'` in the same environment.
